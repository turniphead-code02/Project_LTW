5. Cách Gửi Dữ Liệu Từ Front-end Lên Server (GET, POST, PATCH, DELETE)

Slide 05 / 09

CÁCH 1: PHƯƠNG THỨC GET Truyền Dữ Liệu Qua URL Query String

Khi nào dùng: Khi lấy danh sách, xem chi tiết hoặc lọc việc làm (không làm thay đổi dữ liệu trong DB).
Cách hoạt động: JS đọc giá trị người dùng nhập ở các ô lọc, dùng URLSearchParams ghép vào sau dấu ? trên đường dẫn URL. 

// Ví dụ thực tế trong: job-portal/assets/js/jobs.js
const params = new URLSearchParams();

// 1. Đọc giá trị từ các ô input / select trên giao diện
const keyword = document.getElementById('topKeywordInput').value.trim();
const locationId = document.getElementById('topLocationSelect').value;
const salaryMin = document.getElementById('filterSalaryMin').value;

if (keyword)    params.set('keyword', keyword);
if (locationId) params.set('location_id', locationId);
if (salaryMin)  params.set('salary_min', salaryMin);
params.set('page', currentPage);

// 2. Gửi request GET lên Server:
// URL thực tế: GET http://localhost:5001/api/v1/jobs?keyword=React&location_id=1&page=1
const response = await window.JobPortalAPI.get(`/jobs?${params.toString()}`);

CÁCH 2: POST / PATCH / DELETE Gửi Qua Body (JSON hoặc FormData)

Khi nào dùng: Khi thêm mới (POST), cập nhật một phần (PATCH) hoặc xóa (DELETE).
Cách hoạt động: Đóng gói dữ liệu vào phần body của hàm fetch() và gửi kèm Authorization: Bearer <token> trong Header. 

// A. Gửi dữ liệu chữ bằng JSON (VD: HR đăng tin mới - employer-table.js)
await window.JobPortalAPI.post('/employer/jobs', {
  title: 'Kỹ sư Backend Node.js',
  category_id: 1,
  location_id: 1,
  salary_min: 15000000,
  salary_max: 25000000,
  deadline: '2026-12-30'
}); // -> api.js tự chuyển thành JSON.stringify(body) kèm Content-Type: application/json

// B. Gửi kèm File CV PDF bằng FormData (VD: Ứng viên nộp đơn - job-detail.js)
const formData = new FormData();
formData.append('cover_letter', coverLetterInput.value);
formData.append('cvFile', fileInput.files[0]); // File nhị phân .pdf
await window.JobPortalAPI.post(`/job-detail/${jobId}/apply`, formData);

// C. Cập nhật trạng thái bằng PATCH (VD: Admin duyệt tin - admin.js)
await window.JobPortalAPI.patch(`/admin/jobs/${jobId}/status`, { status: 'approved' });

6. Cách Back-end Xử Lý Dữ Liệu & Trả Kết Quả Về Front-end

Slide 06 / 09

Bước 1 → 3: Back-end Nhận, Kiểm Tra & Chạy SQL

  • Đọc dữ liệu gửi lên: Lấy từ req.query (nếu là GET), req.params.id (lấy ID trên đường dẫn) hoặc req.body (nếu là POST/PATCH).
  • Kiểm tra quyền & điều kiện: Qua requireAuth, requireRole; kiểm tra dữ liệu rỗng/sai định dạng (trả mã 400 nếu sai).
  • Truy vấn MySQL an toàn: Dùng await pool.query(sql, [tham_số]) truyền qua dấu ? để tránh lỗi SQL Injection.
// Ví dụ thực tế tại: backend/src/routes/employer.routes.js
router.post('/jobs', requireAuth, requireRole('employer'), async (req, res) => {
  // 1. Lấy dữ liệu Front-end gửi lên trong req.body
  const { title, category_id, location_id, salary_min, salary_max, deadline } = req.body;
  if (!title) return sendError(res, { code: 400, message: 'Thiếu tiêu đề.' });

  // 2. Thực thi câu lệnh INSERT vào bảng `jobs` trong MySQL
  const [result] = await pool.query(
    `INSERT INTO jobs (company_id, category_id, location_id, title, slug,
                       salary_min, salary_max, deadline, status)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, 'pending')`,
    [companyId, category_id, location_id, title, slug, salary_min, salary_max, deadline]
  );

  // 3. Trả kết quả JSON về cho Front-end (mã 201 Created)
  return sendSuccess(res, {
    code: 201,
    message: 'Đã gửi tin tuyển dụng, đang chờ quản trị viên duyệt.',
    data: { job_id: result.insertId, status: 'pending' }
  });
});

Bước 4: Đóng Gói JSON Trả Về & Front-end Hiển Thị

  • Định dạng JSON thống nhất (utils/response.js): Mọi API đều trả về đối tượng gồm success (true/false), code (mã HTTP), message (câu thông báo) và data (dữ liệu từ DB).
  • Front-end nhận kết quả: Khi await JobPortalAPI... nhận được JSON, JS hiện thông báo Toast và dùng hàm .map() tạo chuỗi HTML gắn vào innerHTML.
// 1. Gói tin JSON thực tế Back-end trả về cho trình duyệt:
{
  "success": true,
  "code": 200,
  "message": "Tra cứu danh sách việc làm thành công.",
  "data": [
    {
      "job_id": 1,
      "title": "Frontend React Developer (Junior / Middle)",
      "company_name": "Công Ty Cổ Phần Công Nghệ VNG",

      "salary_max": "22000000.00"
    }

}

// 2. Front-end (jobs.js) nhận `response.data` và vẽ ra giao diện:
jobsListContainer.innerHTML = response.data.map(job => renderJobCard(job)).join('');

NỘI DUNG BẮT BUỘC 7 (PHẦN 2) // MỐI QUAN HỆ GIỮA CÁC BẢNG

7B. Sơ Đồ Mối Quan Hệ Giữa Các Bảng (1-1, 1-N, N-N) & Ràng Buộc

Slide 08 / 09

1. Quan hệ users — companies Quan hệ 1 – 1

Cột companies.user_id là Khóa ngoại tham chiếu tới users.user_id và được đặt ràng buộc UNIQUE.
Ý nghĩa: Mỗi tài khoản có vai trò Nhà tuyển dụng (role = 'employer') chỉ sở hữu và quản lý đúng 1 hồ sơ công ty duy nhất.

2. Quan hệ companies / categories / locations — jobs Quan hệ 1 – Nhiều (1-N)

Bảng jobs chứa 3 Khóa ngoại: company_id, category_id, location_id.
Ý nghĩa: Một công ty có thể đăng nhiều tin tuyển dụng; một ngành nghề hoặc một tỉnh/thành phố có nhiều tin tuyển dụng thuộc về nó (giúp lọc theo ID chính xác, không bị lệch chính tả).

3. Quan hệ jobs — skills (qua job_skills) Quan hệ Nhiều – Nhiều (N-N)

Một công việc yêu cầu nhiều kỹ năng (VD: cần cả Node.js, SQL, Docker) và một kỹ năng xuất hiện ở nhiều công việc khác nhau.
Cách giải quyết: Tách bảng trung gian job_skills có khóa chính ghép (job_id, skill_id) nối 2 khóa ngoại về 2 bảng.

4. Quan hệ users — resumes, applications, saved_jobs Quan hệ 1 – N & N – N

• users (1) → (N) resumes: Một ứng viên tải lên được nhiều bản CV PDF.
• applications nối users, jobs, resumes và đặt UNIQUE(job_id, user_id) để 1 ứng viên chỉ nộp tối đa 1 đơn cho mỗi công việc.
• saved_jobs dùng khóa chính ghép (user_id, job_id) để lưu danh sách việc làm yêu thích. 

-- Minh họa ràng buộc Khóa ngoại (Foreign Key) & Chống nộp trùng trong database/schema.sql:
UNIQUE KEY `uq_applications_job_user` (`job_id`, `user_id`),
CONSTRAINT `fk_applications_job`    FOREIGN KEY (`job_id`)    REFERENCES `jobs` (`job_id`)       ON DELETE CASCADE,
CONSTRAINT `fk_applications_user`   FOREIGN KEY (`user_id`)   REFERENCES `users` (`user_id`)     ON DELETE CASCADE,
CONSTRAINT `fk_applications_resume` FOREIGN KEY (`resume_id`) REFERENCES `resumes` (`resume_id`) ON DELETE SET NULL

  • Bước 2 — Xem (GET + F5): Mở jobs.html, bấm F5 tải lại trang → tin vừa duyệt hiển thị ngay lên đầu danh sách việc làm.
  • Bước 3 — Thêm & Xóa việc đã lưu (POST / DELETE): Đăng nhập Ứng viên (thanh.tran@student.ut.edu.vn / 123456), bấm Lưu việc làm rồi vào saved-jobs.html bấm Bỏ lưu → kiểm chứng trong bảng saved_jobs.
-- Kiểm chứng sau khi Admin duyệt & Ứng viên Lưu/Bỏ lưu:
SELECT job_id, title, status FROM jobs ORDER BY job_id DESC LIMIT 2;
SELECT * FROM saved_jobs ORDER BY saved_at DESC LIMIT 5;
